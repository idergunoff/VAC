## Реализация

`vac.storage` — необязательный адаптер SQLite без Qt и зависимости от ядра.
`models.py` содержит транспортные dataclass-модели с NumPy-массивами;
`repositories.py` предоставляет прикладной API; `session.py` — соединения,
транзакции и журнал миграций; `codec.py` — NPY без pickle.
Схема поставляется в пакете: `migrations/001_initial.sql`.

Связи: скважина → исследование → оригиналы и упорядоченные каналы → запуск с
точными входами → производные сигналы/статистика → автоматическая интерпретация
→ новая ручная версия → отчёт. Каждая запись получает внутренний UUID.
Номер скважины и имя файла не уникальны. Происхождение включает хеш входного
комплекта (байты, порядок, массивы, роли и преобразования), снимок параметров с
версией формата, версию программы/алгоритма и идентификатор эталонов.

Сохранение исследования, запуска, интерпретации и отчёта — отдельные атомарные
операции `BEGIN IMMEDIATE`/commit/rollback. Исключение, включая прерывание,
откатывает агрегат и созданные им массивы. Готовое исследование/запуск доступно
только после commit. Неуспешную обработку можно явно записать со статусом
`failed`, причиной и без готовых выходов. Такая версия не принимает интерпретацию.
Повторная обработка всегда создаёт новый ID, автоматическая интерпретация и
последующие ручные версии сохраняются отдельно. В API нет перезаписи/удаления
исходников и готовых результатов. SQL-доступ к файлу не является защитой от
злонамеренного редактирования; контрольные суммы обнаруживают повреждения BLOB.

Внешние ключи включены на каждом соединении; составные FK запрещают смешивать
исследования у исходников, каналов, входов и статистики. Проверки репозитория
дополнительно связывают статистику с входами, исправления/интервалы с сигналами
запуска, ручную версию с совместимой базовой интерпретацией и словарём классов.
Удаление связанной скважины/исследования ограничено FK, каскадного удаления нет.
Индексы покрывают исследования скважины, версии исследования, порядок каналов,
отчёты интерпретации и поиск контрольных сумм. Поиск имени скважины — точная
подстрока с поддержкой кириллицы, без обещания регистронезависимого Unicode-поиска.

## Данные и неизвестные значения

- Оригинальные байты LVM/TWF хранятся отдельно от загруженного/преобразованного
  канала. `transformation` записывает версию и параметры преобразования; API не
  угадывает соответствие канала исходнику.
- Физические единицы и смысл технической оси неизвестны: `None`/SQL NULL.
  Неизвестная дата исследования, реквизиты, автор и единицы статистики также
  могут отсутствовать. Служебное время — UTC. Описание может быть пустым.
- Ось канала — непустой конечный вещественный/целочисленный 1D-массив, значения
  — числовой 1D-массив той же длины. Разные каналы могут иметь разные оси.
  Монотонность не предполагается, порядок отсчётов сохраняется. Исходные NaN/Inf
  значений не заменяются NULL. Неизвестные/нечисловые оси нужно сохранять в
  оригинале и явно разбирать до принятия каналов в архив.
- NPY v1 сохраняет dtype, byte order, форму, float64 без округления, NaN/Inf и
  знак нуля. Object/string/structured dtype запрещены. Пустые массивы результатов
  допустимы, пустые сигналы — нет. Статистика также хранит точное числовое значение
  в массиве, включая NaN, с отдельным именем/единицами.
- Для каждого BLOB — SHA-256; массив дополнительно проверяется по размеру,
  заголовку, форме, dtype и кодеку до `np.load(allow_pickle=False)`. Лимит одного
  оригинала/массивного BLOB/отчёта — 256 MiB. Это ограничение первой реализации,
  не целевой размер всего архива. Чтение интервала загружает целый канал и
  выбирает NumPy-маской включительно с обеих сторон.
- Интервалы интерпретации имеют конечные границы, класс из явного словаря и
  правило границ `closed/left/right/open`. Их координаты ссылаются на ось сигнала.
  Правила классификации и последовательность операций задаёт вызывающий сервис.
- Настройки JSON должны быть полным снимком сценария, а не только шестью полями
  `ProcessingParameters`; NaN/Inf в JSON запрещены. Числовые пропуски в результатах
  передаются массивами. Полноту предметных настроек обеспечивает вызывающий сервис
  по `parameter_schema`, слой хранения не придумывает отсутствующие параметры.

## API

```python
from vac.storage import Archive

with Archive('/путь/к/архиву.sqlite') as archive:
    well_id = archive.create_well('Скважина 7', {'месторождение': None})
    # study: Study с Source (байты) и InputChannel (ось, значения, роль,
    # source_ordinal и явные параметры преобразования).
    study_id = archive.save_study(well_id, study)
    restored = archive.open_study(study_id)
    channels = archive.get_channels(study_id)  # устойчивые ID, порядок и данные
    interval = archive.read_interval(channels[0]['id'], 10., 20.)
```

Путь передаётся явно; родительский каталог должен существовать. Доступны
`find_wells`, `list_studies`, `find_sources`, `save_run/open_run/list_runs`,
`save_interpretation/open_interpretation/list_interpretations`,
`save_report/open_report/list_reports`. Возвращаемые массивы принадлежат
вызывающему коду; их изменение не изменяет БД. Соединение/SQL-строки не передаются
в вычисления или виджеты. Минимальный полный пример с обработкой, корректировкой
и DOCX находится в `tests/integration/test_storage.py`.

`find_sources` отдельно возвращает `same_content` и `same_name` в существующих
контекстах. `save_study` всегда добавляет новое исследование: одинаковое
содержимое в разных исследованиях и одно имя с разными байтами сохраняются.
Это явная политика повторного импорта; автоматического слияния нет.

## Миграции

Открытие архива применяет упорядоченные SQL-файлы и записывает имя, SHA-256 и
время применения в `schema_migration` одной транзакцией. Повторное открытие
проверяет журнал; изменённая или неизвестная миграция вызывает ошибку. DDL и
журнал откатываются вместе при сбое. `executescript` не используется из-за его
неявного commit. Новые изменения схемы добавляются следующим SQL-файлом,
существующие файлы не редактируются. Откат версии схемы не реализован.
Busy timeout — 5 с, обычный rollback journal, настройки durability не снижены.

## Проверки и границы

```sh
python -m unittest discover -s tests/integration -p test_storage.py -v
python -m unittest discover -s tests/unit -v
QT_QPA_PLATFORM=offscreen MPLBACKEND=Agg python -m unittest discover -s tests/integration -v
```

См. `validation.json`. Проверены создание и повтор миграции, неверная контрольная
сумма/будущая версия, откат DDL и частичных агрегатов, FK/удаление, кириллица и
пробелы, дубликаты, повторное открытие, точность обоих исходных комплектов,
особые float-значения, независимые версии обработки/интерпретаций, связь отчёта,
повреждение данных и чтение включительного интервала. Устанавливаемый wheel
проверяется из чужого каталога с созданием и открытием архива.

В системном Python стоят NumPy 2.3.5/SciPy 1.17.0 и отсутствует Qt: первый общий
прогон там дал 5 численных несовпадений и ошибку импорта Qt. Основная приёмка
выполнена в `/workspace/.venvs/vac` с закреплёнными версиями проекта; допуски,
формулы, UI и эталоны не менялись. Новые проверки хранения проходят и в системном
Python.

GUI, массовый импорт и перенос `.vac` — этап 8; резервные копии, аварийные
сценарии рабочего архива и масштабные блокировки — этап 9. Windows не проверена.
Рабочие объёмы и многопользовательский режим остаются ограничениями ADR-001.
Идентификаторы старого кода/эталонов сохраняют происхождение, но сами по себе не
заменяют доступность соответствующей поставки алгоритма для повторного расчёта.
