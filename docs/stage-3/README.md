# Этап 3 — явная модель состояния

Дата: 20 октября 2026 года.

Статус: реализован и технически проверен на Linux/Python 3.12, Qt offscreen.
Windows и визуальная приёмка реального GUI остаются открытыми.
Исходный коммит: `52a7c25f2862cb181b8cc5a82a39452a7180c892`.

## Выполненные задачи

- Добавлены сущности измерений, каналов, параметров, результата, интервалов,
  ручных корректировок и реквизитов отчёта в `vac/domain/models.py`.
- Создано независимое состояние двух типов оборудования, без глобальных таблиц
  и singleton. Все прежние функции основной версии стали методами контроллера.
- Заданы очистка, отмена загрузки, устаревание результатов, принадлежность ручных
  правок сигналу и владение изменяемыми данными. См. [жизненный цикл](lifecycle.md).
- Основные циклы расчёта и классификация перенесены в `vac/calculation.py` с явными
  входами и без Qt. Формулы, DataFrame, столбцы и индексация сохранены.
- Подготовлен необходимый минимум отсутствовавшего этапа 2: пакет, `pyproject.toml`,
  запуск `python -m vac`, совместимый `VAC_python.py`, сборка GUI в явной функции,
  шаблон относительно установленного пакета. Mini-файлы и формы не изменялись.
- Регрессионные инструменты получают контроллер через тестовое read-only
  представление `tools/application_scope.py`, а не создают глобальный state.

## Проверки и воспроизведение

Из корня проекта после установки зависимостей:

```sh
python -W ignore -m unittest discover -s tests/unit
python -W ignore -m unittest discover -s tests/integration
python tests/check_regression_compare.py
python tools/smoke.py --scenario launch
python tools/regression.py record --device new --output work/stage3-new
python tools/regression.py record --device old --output work/stage3-old
python tools/check_stage3_regression.py --baseline tests/baselines/stage-1/new --actual work/stage3-new
python tools/check_stage3_regression.py --baseline tests/baselines/stage-1/old --actual work/stage3-old
```

`--output` должен быть новым каталогом. В этой сессии итоговые прогоны находятся
в `work/stage3-accept-new` и `work/stage3-accept-old`; временные результаты не
включаются в git. Эталоны этапа 1 не изменены.

Проверяются:

- Численные расчёты обоих типов оборудования без QApplication: повторный расчёт,
  сохранность входных таблиц, сравнение с массивами этапа 1 (`rtol=atol=1e-12`).
- Два независимых окна, отмена выбора файлов/каталогов, устаревание при смене
  параметров, очистка ревизии и ручной истории, действия до выбора сигнала.
- FULL-сценарии LVM/TWF: шаги 01–10 (массивы, классы, графики, настройки и данные
  DOCX) сравниваются прежним строгим компаратором.
- Шаг 11: сигналы, статистика и цементограмма совпадают; разрешено только удаление
  влияния прежних ручных интервалов на классификацию остальных каналов, в их
  пределах с запасом 17 отсчётов на legacy-фильтрацию коротких интервалов.
- Шаг 12: отсутствуют прежняя цементограмма, ручные интервалы и названия сумм
  в статистике после повторной загрузки.
- Импорт `vac`/`VAC_python` не импортирует Qt и не запускает GUI. Wheel собирается
  с ресурсом Word и модулями основной формы.

## Ожидаемые отличия от этапа 1

1. Отмена загрузки теперь сохраняет открытое исследование.
2. Повторная загрузка очищает статистику, интерпретацию, настройки отчёта и ручные
   интервалы прежнего набора.
3. При восстановлении `.vac` чужие ручные интервалы больше не накладываются
   на автоматическую классификацию всех каналов. Классификация выбранной
   цементограммы и сохранённый Word-отчёт сохраняют эталонный результат.

Поэтому полное сравнение `tools/regression.py compare` с эталоном этапа 1
ожидаемо завершается ошибкой на шагах 11–12. Отдельный `check_stage3_regression.py`
проверяет неизменные сценарии и ограниченные ожидаемые отличия; общий строгий
компаратор не ослаблен.

## Ограничения и следующий шаг

Исходные ограничения этапов 0–1 остаются: нет Windows/визуальной приёмки и
предметного подтверждения качества интерпретации. Сохранены предупреждения
pandas о chained assignment и фрагментации. Работа с ошибочным/неполным комплектом
не стала атомарной; восстановление из pickle по-прежнему только для доверенных
`.vac`. Конкретные ошибки legacy вне жизненного цикла здесь не исправлялись.

Следующий шаг — этап 4: последовательно отделять загрузчики LVM/TWF, суммирование,
PDF и прочие вычисления от оставшегося контроллера, сравнивая каждый перенос.
