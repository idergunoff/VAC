# Этап 2: каркас пакета и единый запуск

20 октября 2026. Техническая часть выполнена на Linux/Python 3.12.14, Qt offscreen.
Полная платформенная приёмка открыта: Windows и реальный GUI не проверены.
Исходный коммит: `52a7c25f2862cb181b8cc5a82a39452a7180c892`, рабочая копия перед
изменениями чистая. Ограничения этапов 0 и 1 сохраняются.

## Выполнено

- `vac/__init__.py`, `vac/app.py`, `vac/__main__.py`: пакет и единый вход
  `python -m vac`, консольная команда `vac`.
- `vac/legacy.py`: прежняя прикладная логика с явными `create_window`,
  `connect_signals`, `run`. QApplication, форма, дата, proxy мыши и подключения
  сигналов создаются только при запуске. Порядок подключений сохранён, включая
  прежнее повторное подключение `check_int_sig`.
- `VAC_python.py`, `VAC_python_mini.py`: защищённые совместимые стартеры основной
  формы, без дублирования логики и без выбора формы.
- `docs/history/mini`: прежние mini-программа и формы без изменения байтов;
  архив не входит в установленный пакет и не сопровождается отдельно.
- `vac/reference.py`: прежние массивы без изменения байтов; `standard.py` —
  совместимый явный импорт. Wildcard-импорты формы и кривых из legacy удалены.
- `vac/resources/template.docx`: прежний шаблон без изменения байтов. Его путь
  вычисляется относительно установленного пакета. `cement_temp`, `save_cement`
  используют этот путь. Выходные пути остаются относительно рабочего каталога.
- `pyproject.toml`, `MANIFEST.in`: сборка wheel и исходного дистрибутива,
  прежние закреплённые прямые зависимости из `requirements.txt`, ресурсы,
  совместимые модули и консольный вход. В sdist включены `.ui` и генератор.
- `tools/generate_ui.py`: PyQt5 5.15.11, генерация основной формы с прежним
  автоматическим responsive-hook. Изменения `VAC_dialog.py` относительно базы —
  только два комментария о пути исходника и версии генератора. `.ui` и
  `responsive_layout.py` не изменены.
- Инструменты smoke/регрессии читают состояние из реального модуля обработчиков,
  проверяют пакетный шаблон без копирования в рабочий каталог и фиксируют новые
  пути исходников в манифесте. Компаратор, допуски и эталоны не изменены.
  Статическая инвентаризация читает `vac/legacy.py` и сохраняется в
  `work/inventory`, не меняя исторические артефакты этапа 0. Проверка компоновки теперь
  охватывает только сопровождаемую основную форму.

## Ограничения и следующий шаг

Windows, реальные диалоги, шрифты, визуальная проверка графиков и отчётов требуют
отдельного прогона. Проверка нескольких размеров offscreen не заменяет приёмку
на небольшом экране. Полная приёмка сценариев этапа 1 остаётся открытой.

Глобальное состояние намеренно остаётся в `vac.legacy`, одно окно на процесс.
Пакет пока не является независимым вычислительным ядром: это работа этапов 3–4.
`vac` и `vac.app` импортируются без Qt и записи файлов; `vac.legacy` загружает
научные библиотеки, но не создаёт окно и не запускает event loop.

Следующий структурный шаг — этап 3: явное состояние и жизненный цикл данных,
с повторным сравнением обоих FULL-сценариев после каждого переноса ответственности.
