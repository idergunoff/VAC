# Черновая схема для этапа 7

Это контракт для обсуждения и реализации, не применённая SQL-миграция.
Все ID — внутренние суррогатные ключи. Время служебных событий — UTC;
неизвестная дата исследования и неизвестные единицы допускают NULL.
Номер скважины и имя файла не являются глобальными ключами.

| Сущность | Основные поля и связи |
| --- | --- |
| `well` | id, имя/номер, месторождение и другие известные реквизиты; NULL для неизвестного |
| `study` | id, well_id FK, дата, оборудование new/old, описание, версия загрузчика, состояние комплекта |
| `source_file` | id, study_id FK, относительное исходное имя, порядок импорта, формат, размер, SHA-256, оригинальные байты BLOB |
| `numeric_array` | id, кодек npy-v1, dtype, shape, размер, SHA-256, payload BLOB; неизменяемое содержимое |
| `axis` | id, массив FK, смысл/единицы (NULL если неизвестны), длина, признак монотонности |
| `channel` | id, study_id FK, source_file_id FK, ordinal, роль signal/noise, axis_id FK, values_array_id FK, версия преобразования и его параметры |
| `processing_run` | id, study_id FK, версия/хеш входного комплекта, параметры JSON с версией формата, версия кода, алгоритма и хеш эталонов, создано UTC, статус |
| `run_input` | run_id FK, channel_id FK, ordinal; точные входные каналы запуска |
| `result_signal` | id, run_id FK, имя/назначение, axis_id FK, values_array_id FK; исходное и производное не смешиваются |
| `result_statistics` | run_id FK, channel_id FK, именованные показатели, известные единицы; точные значения, без округления отчёта |
| `interpretation` | id, run_id FK, базовая автоматическая версия, итоговые массивы, версия системы классов; новая ручная версия не перезаписывает старую |
| `manual_correction` | id, interpretation_id FK, исходная версия/сигнал, ordinal, операция, параметры JSON, автор если известен, создано UTC |
| `quality_interval` | interpretation_id FK, ordinal, начало, конец, класс, система координат/axis_id FK; явные правила включения границ |
| `report` | id, interpretation_id FK, реквизиты JSON, версия/хеш шаблона, создано UTC, формат, SHA-256, документ BLOB |
| `schema_migration` | версия PK, контрольная сумма, время применения; миграция применяется транзакционно |

Оригинальный файл и нормированный/интерполированный канал TWF не равны:
`MeasurementSet.original` — снимок уже загруженных данных. Для воспроизводимости
необходимо хранить оба уровня, а не называть снимок байтовым оригиналом.
Для LVM сохраняются исходные знаки и все исходные столбцы в оригинальных байтах,
даже если рабочий канал использует абсолютное значение.

Структура сопоставляется с текущими `MeasurementSet`, `ProcessingParameters`,
`ManualCorrection`, `Interpretation` и `ReportDetails` в `vac/domain/models.py`.
Модель архива дополняет их происхождением/версиями; расчёты продолжают работать
с DataFrame/NumPy. Снимок параметров охватывает все влияющие настройки, включая
порядок операций, выбор каналов/сумм, пороги, интервалы и нормирование; шести
полей `ProcessingParameters` недостаточно для полного сохранения GUI-сценария.
Legacy `.vac` переносит только фактически имеющиеся поля через отдельный адаптер.

## Ограничения и индексы

- FK обязательны и включаются на каждом соединении. Принадлежность источников,
  каналов и запусков одному исследованию проверяется составными FK/ограничениями
  или транзакционным репозиторием; одного FK на существующий ID недостаточно.
- Уникальны `(study_id, ordinal)` у каналов, `(run_id, ordinal)` у входов,
  `(interpretation_id, ordinal)` у исправлений/интервалов. Роль шума и число каналов
  проверяются по оборудованию перед фиксацией готового комплекта.
- SHA-256 индексируется для поиска повторов, но не уникален на уровне всего
  архива: один файл может иметь разные контексты импорта. Дедупликация байтов
  возможна позже без потери записей происхождения.
- Индексы: well по имени/номеру, study по well_id/дате, run по study_id/времени,
  channel по study_id/ordinal, report по interpretation_id. Для начального BLOB
  не обещается SQL-индекс по отдельным отсчётам глубины.
- Непустые массивы имеют согласованные dtype/shape/длину оси; неизвестные единицы
  не заменяются метрами. Начало интервала не больше конца; допустимые классы
  фиксируются версией классификации, исходные NaN/Inf не теряются.
- Исходники/готовые версии неизменяемы через прикладной API. Удаление исследования
  с результатами по умолчанию RESTRICT; явное удаление всего графа — отдельная
  транзакция с проверкой внешних ссылок. Скважина с исследованиями не удаляется
  каскадно случайной операцией. Очистка общих массивов требует проверки ссылок.

## Транзакции и проверки этапа 7

Сначала чтение и валидация файлов вне write-транзакции, затем короткая атомарная
запись комплекта, оригиналов и каналов. Статус «готово» появляется только после
успешного commit. Для обработки сохраняются отдельные входы и результат, новая
версия получает новый ID. При ошибке не остаются «готовые» неполные версии.

Обязательны проверки пустой БД и повторного запуска миграций, отката при ошибке
в середине записи, FK и удаления, точного roundtrip обоих примеров и особых
float-значений, кириллицы/пробелов, двух одинаковых имён с разным содержимым,
одинакового файла в двух исследованиях, сохранения нескольких обработок и ручных
версий. Миграции существующего архива, блокировки и восстановление копии проверяются
на копиях. Тест временной схемы бенчмарка не заменяет эти проверки.
