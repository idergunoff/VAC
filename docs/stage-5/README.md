## Разделение ответственностей

| Прежняя функция / операция | Новый модуль | Что остаётся в контроллере |
| --- | --- | --- |
| `choice_signal`, `plot_graph*`, `draw_cement` | `vac/gui/plotting.py` | Снимок параметров и передача цели pyqtgraph |
| `draw_total_cement`, `draw_match_def`, `all_cement*`, `choice_cement` | `vac/reporting/figures.py` | Выбор каналов, чтение порогов, сообщение результата |
| Рисование в `cementogramma` | `vac/reporting/figures.py:cementogramma` | Вызов классификации, экспорт таблицы, сбор прежнего словаря настроек |
| `draw_graphics*`, график `corr_matrix` | `vac/reporting/figures.py` | Чтение настроек, подготовка ранговой таблицы, сообщения |
| Подстановка в Word из `save_cement` | `vac/reporting/word.py:build_report` | Снимок реквизитов, вызов сборки, сохранение и сообщение |
| Все TXT/PNG/DOCX-записи | `vac/io/exports.py` | Выбор прежнего имени и момента записи |
| `pickle.load/dump` | `vac/io/legacy_options.py` | Диалог выбора и применение настроек в прежнем порядке |
| Массивы из `standard.py` | `vac/reference.py` | Данных эталонов в контроллере больше нет |

Визуальные функции получают явное состояние/таблицу, словарь скалярных настроек
и, для интерактивных кривых, цель pyqtgraph. Контроллер и виджеты формы им не
передаются. Ключи словаря отображения пока сохраняют имена прежних полей и тип
чтения (`checkState`, `value` и т. п.), чтобы перенос проверялся без изменения
семантики. `read_display_values` считывает эти поля до рисования; это обычные
значения, а не прокси к GUI. Word получает таблицу интерпретации, частоту,
реквизиты и путь шаблона; его можно собрать без QApplication.

Привязки в `bind_signals` не менялись. В том числе сохранены два подключения
`doubleSpinBox_int_max.valueChanged → check_int_sig`, сигналы инвалидирования и
порядок каскадных вызовов. Их устранение не входит в перенос. Состояние,
загрузчики, расчётные модули и сервис этапа 4 не переписаны, формулы и пороги
не менялись. Подготовка рангов для корреляционной матрицы остаётся небольшой
операцией контроллера, не частью интерпретационного ядра.

Печатные графики сохраняют прежние побочные эффекты: `draw_graphics` добавляет
столбцы `sum5/sum2` к рабочей таблице; начало оси и заполнение классов, размеры
листов, подписи, порядок `tight_layout/savefig/suptitle/show` сохранены.
Отдельное будущее изменение может сделать рисование полностью неизменяющим.

## Контракт шаблона Word

Шаблон поставляется в `vac/resources/template.docx`, путь разрешается независимо
от рабочего каталога. Это фиксированный шаблон, а не произвольный DOCX:

- Первый верхнеуровневый `doc.tables[0]` содержит 10 строк (0–9); используются
  адреса ячеек и runs в строках 0, 1, 2, 3, 6, 7, 9. В строке 6 вставляется PNG.
- Вторая таблица содержит вложенную таблицу интервалов в ячейке `[0, 0]`
  с четырьмя столбцами: начало, конец, длина, класс. Интерпретатор также
  подставляется в `[1, 1]` второй таблицы.
- Используются абзацы документа 4, 6, 7, 9, 11 и конкретные runs; изменение
  разбиения текста на runs требует изменения адаптера и повторной проверки.
- При максимальной глубине строго больше 400 первая таблица клонируется,
  вставляется `temp1.png`, появляется «лист 2»; строго больше 800 — `temp2.png`
  и «лист 3». Ровно 400/800 дополнительную страницу не включают.
- Шрифты, размеры, выравнивание, формулировки трубы и режим Гольфстрим сохранены.
  Совместимость DOCX проверяется по содержимому и изображениям, не ZIP-метаданным.

Сохраняется legacy-ограничение построения интервалов отчёта: если новый интервал
начинается ровно на последнем отсчёте, код может обратиться к отсутствующей строке
вложенной таблицы. При проверке пагинации использован непустой завершающий интервал.
Исправление этой ошибки требует отдельного изменения ожидаемого поведения.

## Файловая совместимость

TXT сохраняются с табуляцией и индексом pandas. PNG — с прежними именами и DPI.
DOCX и `.vac` имеют прежние имена. Все относительные выходы остаются в текущем
рабочем каталоге и перезаписываются при повторном действии. Список имён:
[каталог выходов](../stage-0/outputs.md). Шаблон не перезаписывается.

`.vac` — прежний pickle-словарь с диапазоном обработки, пределами и порогами
цементограммы, именем сигнала и `corr_sig`. Это не архив исследования: нужны уже
загруженные совместимые исходные данные. Протокол и поля не менялись, для обоих
эталонных файлов сохранение через адаптер даёт те же байты.

**Загружать только `.vac` из доверенного источника:** pickle может исполнять код.
Чтение изолировано в явно названной функции `load_trusted`; это не песочница и
не проверка доверия. Будущий безопасный формат должен иметь явную версию схемы
и отдельный путь миграции. Он не вводился в рамках совместимого переноса.

Ошибки и пути вывода намеренно не менялись в этой группе изменений. В частности,
при отмене диалога `.vac` остаётся прежнее ошибочное поведение, а `.vac` может
записываться после перехваченного PermissionError записи DOCX. Улучшения сообщений,
отмены, атомарности набора экспортов и выбора каталога вывода — отдельная задача
после стабилизации с проверками сохранности уже существующих файлов.

`standard.py` уже был совместимым явным импортом с этапа 2. Добавлен `__all__`
канонического `vac.reference`; печатные графики импортируют шесть имён явно.
Массивы не переводились в другой формат. Зафиксированы длины и SHA-256
little-endian float64 всех шести кривых: проверяются значения и порядок.

## Проверки

Зависимости и команды запуска — в корневом README. Проверки запускаются из корня:

```sh
python -W ignore -m unittest discover -s tests/unit
python -W ignore -m unittest discover -s tests/integration
python tests/check_package.py
python tools/generate_ui.py --check
python tests/check_regression_compare.py
python tools/regression.py record --device new --output work/stage5-new
python tools/regression.py record --device old --output work/stage5-old
python tools/check_stage3_regression.py --baseline tests/baselines/stage-1/new --actual work/stage5-new
python tools/check_stage3_regression.py --baseline tests/baselines/stage-1/old --actual work/stage5-old
python tools/check_stage5_presentation.py --output work/stage5-presentation
```

Каталоги `--output` должны быть новыми. Инструмент расширенного сравнения читает
настоящий контроллер из фиксированного коммита `f56fcc5` через `git show`; этот
объект должен быть доступен локально. Он не использует текущий код как эталон и
не обновляет эталоны. В двух режимах порогов сравниваются интерактивные кривые,
все/выбранные цементограммы, исходные графики обоих устройств и корреляция:
оси, подписи, линии, пиксели RGBA, байты PNG и статус GUI.

Проверки нового слоя в `tests/integration/test_presentation.py`: точное
восстановление и побайтовое сохранение доверенных `.vac`; все значения и порядок
эталонов; пагинация 400/401/800/801, два режима отчёта, четыре типа труб;
импорт отчётов без Qt. Эти проверки дополняют прежние FULL-сценарии и тесты ядра.
`tools/regression.py` теперь фиксирует хеши новых модулей в манифесте.

Сводка фактических результатов — [validation.json](validation.json).

## Ограничения и следующий шаг

Техническая приёмка выполняется на Linux/Python 3.12, Qt offscreen/Agg.
Windows, реальный GUI и визуальная вёрстка Word остаются непроверенными;
полная платформенная приёмка фазы A не объявляется завершённой. Численные
эталоны подтверждают совместимость, а не предметную правильность метода.
Mini сохранена как исторический материал, запуск совместимого mini-скрипта
открывает основную форму. База данных не добавлялась.

Отдельная будущая задача небольших экранов: согласовать минимальный размер
окна и масштабы Windows/Linux, проверить доступность каждого действия и графика
на реальном экране; при необходимости доработать существующие Qt-layout,
прокрутку и сворачиваемые панели. Не создавать вторую копию вычислений или
контроллеров. Существующая responsive-компоновка в этой работе не меняется.

Следующий структурный этап — 6: требования к архиву и выбор хранения.
Открытые платформенные сценарии, ошибки legacy и задача небольших экранов
продолжают отслеживаться отдельно.
