# VAC

Настольная интерпретация виброакустической цементометрии. Основная версия — пакет `vac` и форма `VAC_dialog.ui`/`VAC_dialog.py`. Mini-версия не используется; её исходники сохраняются как исторические.

## Установка и запуск

Исходная конфигурация: **Python 3.12, 64 бит**. Прямые зависимости зафиксированы в `requirements.txt`. Проверена установка и headless-запуск на Linux; инструкции для Windows подготовлены, но выполнение на Windows и визуальная проверка обеих платформ ещё требуются. Результаты и ограничения: [этап 0](docs/stage-0/README.md).

Windows, PowerShell (из корня распакованного/клонированного проекта):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m vac
```

Linux, терминал с графической сессией (из корня проекта):

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m vac
```

На Debian/Ubuntu для Qt могут потребоваться системные библиотеки `libgl1`, `libegl1`, `libxkbcommon-x11-0`, `libxcb-xinerama0` и зависимости XCB. Если Qt сообщает о недостающем плагине xcb, выясните отсутствующие библиотеки через `ldd` для `PyQt5/Qt5/plugins/platforms/libqxcb.so`; headless-плагин не заменяет проверку реального GUI.

После установки запускать `python -m vac` или `vac` можно из любого каталога.
Совместимые `python VAC_python.py` и `python VAC_python_mini.py` запускают ту же
основную форму. Mini-исходники перенесены в `docs/history/mini` и не входят в пакет.
Для разработки используйте `python -m pip install -e .`.

`template.docx` поставляется в `vac/resources`, эталонные кривые — в
`vac/reference.py`; их поиск не зависит от рабочего каталога. Программа по-прежнему
создаёт и перезаписывает TXT/PNG/DOCX/VAC в **текущем рабочем каталоге**.
Перед опытом сохраните прежние результаты и выберите доступный для записи каталог.
Шаблон меняйте в `vac/resources/template.docx`, затем переустановите пакет.
Соблюдайте регистр имён. Для путей с пробелами используйте кавычки.

## Структура и формы

`vac.app:main` — единая точка входа. `create_window()` явно создаёт окно и
контроллер; каждый контроллер владеет отдельным `ApplicationState` с наборами
нового и старого оборудования. `vac.legacy` сохраняет совместимые функции запуска,
без глобального состояния. Импорт `vac`, `vac.app`, `vac.reference` и стартовых
скриптов не загружает Qt, не создаёт окно и не запускает обработку.
`standard.py` оставлен как совместимый импорт кривых.

Исходник основной формы — `VAC_dialog.ui`; `VAC_dialog.py` генерируется, вручную
его не редактировать. Используется **PyQt5/pyuic 5.15.11** из закреплённых зависимостей:

```sh
python tools/generate_ui.py
python tools/generate_ui.py --check
```

Генератор вызывает `python -m PyQt5.uic.pyuic -x VAC_dialog.ui`, затем автоматически
добавляет прежний вызов `responsive_layout.apply_responsive_layout` перед
`connectSlotsByName`. Компоновка и `.ui` на этапе 2 не изменялись. Исторические
mini-формы не регенерируются. `.ui` и инструмент генерации включены в исходный
дистрибутив; установленному wheel достаточно сгенерированной формы.


Пакет `python-docx` предоставляет импорт `docx`; пакет `docx` устанавливать не нужно. `numpy`, `pandas`, `scipy` — расчёты, `PyQt5`, `pyqtgraph` — GUI и графики, `matplotlib`, `seaborn` — дополнительные графики. Остальные импорты из стандартной библиотеки и файлов проекта. Отдельных внешних инструментов разработки для текущих проверок не требуется: инструменты в `tools/` используют стандартную библиотеку и зависимости приложения. Установка pytest не нужна.

## Проверки без рабочего стола

Из корня проекта, используя Python виртуального окружения:

```sh
python tools/inventory.py
python tools/smoke.py --scenario launch
python tools/smoke.py --scenario new
python tools/smoke.py --scenario old
```

На Linux вместо `python` используйте `.venv/bin/python`, на Windows — `.\.venv\Scripts\python.exe`. Smoke запускает приложение с Qt offscreen, временно подменяет диалог выбора каталога, проверяет создание окна и чтение шаблона; файлы вывода изолирует во временном каталоге с пробелами и кириллицей. Статическая инвентаризация сохраняется в `work/inventory`, не перезаписывая исторический отчёт этапа 0. Код возврата 0 означает прохождение, 1 — ошибку. На случай зависания ограничьте запуск внешним таймаутом (например, `timeout 30` на Linux). Ошибки слотов Qt также приводят к провалу проверки. Smoke не проверяет физическую корректность метода, шрифты и реальный диалог выбора файлов.

Для точного повторения проверенного Linux-набора используйте `docs/stage-0/requirements-linux-py312.lock.txt` вместо `requirements.txt`. Это снимок всех установленных версий для Linux/Python 3.12, без хешей дистрибутивов; его переносимость на Windows не проверена. `requirements.txt` фиксирует только прямые зависимости. Не обновляйте библиотеки одновременно с фиксацией исходного поведения.

## Проверки пакета (этап 2)

```sh
python tests/check_package.py
python tools/generate_ui.py --check
python tests/check_responsive_layout.py
python tests/check_regression_compare.py
```

`check_package.py` проверяет импорт без запуска GUI, ресурсы и три варианта запуска
из временного каталога с пробелами и кириллицей. Для проверки установленного wheel
задайте `VAC_TEST_PACKAGE_PATH` равным каталогу его установки. Результаты этапа 2
и оставшиеся ограничения описаны в `docs/stage-2/README.md`.


## Явное состояние и проверки этапа 3

[Отчёт этапа 3](docs/stage-3/README.md) и
[жизненный цикл состояния](docs/stage-3/lifecycle.md) описывают владение
таблицами, очистку при загрузке и ожидаемые отличия от legacy при восстановлении
`.vac`. Основные вычислительные проходы проверяются без Qt:

```sh
python -W ignore -m unittest discover -s tests/unit
python -W ignore -m unittest discover -s tests/integration
```

Полное старое сравнение этапа 1 ожидаемо обнаруживает изменения очистки состояния;
команды проверки неизменных сценариев и новых правил приведены в отчёте этапа 3.
