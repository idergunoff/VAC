# VAC

Настольная интерпретация виброакустической цементометрии. Основная версия — пакет `vac` и форма `VAC_dialog.ui`/`VAC_dialog.py`. `VAC_python.py` — совместимый стартовый скрипт. Mini-версия не используется; её исходники сохраняются как исторические.

## Установка и запуск

Исходная конфигурация: **Python 3.12, 64 бит**. Прямые зависимости зафиксированы в `requirements.txt`. Проверена установка и headless-запуск на Linux; инструкции для Windows подготовлены, но выполнение на Windows и визуальная проверка обеих платформ ещё требуются. Результаты и ограничения: [этап 0](docs/stage-0/README.md).

Windows, PowerShell (из корня распакованного/клонированного проекта):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m vac
```

Linux, терминал с графической сессией (из корня проекта):

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m vac
```

На Debian/Ubuntu для Qt могут потребоваться системные библиотеки `libgl1`, `libegl1`, `libxkbcommon-x11-0`, `libxcb-xinerama0` и зависимости XCB. Если Qt сообщает о недостающем плагине xcb, выясните отсутствующие библиотеки через `ldd` для `PyQt5/Qt5/plugins/platforms/libqxcb.so`; headless-плагин не заменяет проверку реального GUI.

При запуске из исходников используйте корень репозитория. Для установки пакета:
`python -m pip install .`; после установки доступны `vac` и `python -m vac` из
любого каталога. `python VAC_python.py` сохраняется как совместимый запуск.
Импорт пакета и стартового скрипта не создаёт окно.

Шаблон читается из `vac/resources/template.docx` относительно пакета. Это рабочая
копия шаблона; корневой `template.docx` сохранён для исторических инструментов и
эталонов. Эталонные массивы по-прежнему предоставляет устанавливаемый модуль
`standard.py`. Каталог запуска остаётся каталогом вывода TXT/PNG/DOCX/VAC, где
программа может перезаписать прежние файлы. Перед опытом сохраните результаты.
Соблюдайте регистр имён, пути с пробелами заключайте в кавычки.

`.ui` — исходники форм, `.py` — сгенерированные формы. В этой задаче формы не
менялись. Исторический заголовок указывает генератор 5.15.2; текущая зависимость
PyQt5 закреплена на 5.15.11. Для проверки генерации сначала создавайте файл в
`work/`: `python -m PyQt5.uic.pyuic VAC_dialog.ui -o work/VAC_dialog.generated.py`.
Не редактируйте сгенерированную форму вручную и не заменяйте текущий файл без
проверки diff: в нём уже есть историческое подключение `responsive_layout`,
которое обычная генерация из `.ui` не воспроизводит. Перенос этого подключения
и проверка регенерации относятся к дальнейшей работе с GUI.


Пакет `python-docx` предоставляет импорт `docx`; пакет `docx` устанавливать не нужно. `numpy`, `pandas`, `scipy` — расчёты, `PyQt5`, `pyqtgraph` — GUI и графики, `matplotlib`, `seaborn` — дополнительные графики. Остальные импорты из стандартной библиотеки и файлов проекта. Отдельных внешних инструментов разработки для текущих проверок не требуется: инструменты в `tools/` используют стандартную библиотеку и зависимости приложения. Установка pytest не нужна.

## Проверки без рабочего стола

Из корня проекта, используя Python виртуального окружения:

```sh
python tools/inventory.py
python tools/smoke.py --scenario launch
python tools/smoke.py --scenario new
python tools/smoke.py --scenario old
```

На Linux вместо `python` используйте `.venv/bin/python`, на Windows — `.\.venv\Scripts\python.exe`. Smoke запускает исходное приложение с Qt offscreen, временно подменяет диалог выбора каталога, проверяет создание окна и чтение шаблона; файлы вывода изолирует во временном каталоге с пробелами и кириллицей. Код возврата 0 означает прохождение, 1 — ошибку. На случай зависания ограничьте запуск внешним таймаутом (например, `timeout 30` на Linux). Ошибки слотов Qt также приводят к провалу проверки. Smoke не проверяет физическую корректность метода, шрифты и реальный диалог выбора файлов.

Для точного повторения проверенного Linux-набора используйте `docs/stage-0/requirements-linux-py312.lock.txt` вместо `requirements.txt`. Это снимок всех установленных версий для Linux/Python 3.12, без хешей дистрибутивов; его переносимость на Windows не проверена. `requirements.txt` фиксирует только прямые зависимости. Не обновляйте библиотеки одновременно с фиксацией исходного поведения.

## Явное состояние и проверки этапа 3

[Отчёт этапа 3](docs/stage-3/README.md) и
[жизненный цикл состояния](docs/stage-3/lifecycle.md) описывают модель, владение
таблицами, очистку при загрузке и ожидаемые отличия от legacy при восстановлении
`.vac`. Основные вычислительные проходы проверяются без Qt:

```sh
python -W ignore -m unittest discover -s tests/unit
python -W ignore -m unittest discover -s tests/integration
```

Полное старое сравнение этапа 1 ожидаемо обнаруживает изменения очистки состояния;
команды проверки неизменных сценариев и новых правил приведены в отчёте этапа 3.
